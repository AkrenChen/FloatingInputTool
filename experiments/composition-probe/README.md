# 原生合成验证样机

这是独立实验，不是正式版迁移。使用独立 Tauri 应用标识，不读取正式版设置/草稿、不注册全局快捷键、不写笔记、不生成安装包。关闭样机时会关闭它的动态背景参照窗口；输入和参数不持久化。

## 构建与启动

在仓库根目录运行：

```powershell
cargo run --release --offline --manifest-path experiments/composition-probe/Cargo.toml --target-dir tauri-app/src-tauri/target
```

可执行文件：`tauri-app/src-tauri/target/release/floating-composition-probe.exe`。

需要 Windows 11 build 22000+、支持 Composition 的图形环境和 WebView2 Runtime。本次实际机器 build 26200。尚未验证 Windows 10、另一台机器、远程桌面或系统禁用透明度时的表现。

## 如何调试

1. 保持动态网格参照窗口在样机后方，它是单独的原生窗口，包含细字、网格、移动色块和动态计数。
2. 选择“模拟聚焦”，固定效果，避免调参时窗口焦点改变影响对比。
3. 底板浓度不变时比较“附加模糊”0 与 64；底板浓度是独立的覆盖色透明度。
4. 阴影范围 0 为硬边，增大会向外扩散；浓度 0 关闭自绘阴影，垂直偏移改变其位置。范围是 Composition DropShadow 的 BlurRadius，不等于阴影最外沿距离。
5. 圆角参数只影响样机；正式版仍使用之前选定的系统圆角。
6. “显示参数”提供可选择复制的 JSON。没有自动覆盖系统剪贴板。
7. “跟随焦点”用于真实聚焦/失焦；底部显示实际使用的参数组及原生对象读回的底板和阴影值。
8. “聚焦 / 失焦文字/按钮不透明度”只控制界面，范围 10%–100%，最终选定 100% / 34%。JSON 沿用 `focusedOpacity` / `idleOpacity`，不再表示 HWND 整窗 alpha。
9. “聚焦 / 失焦磨砂覆盖强度”独立控制原生磨砂层，范围 0%–100%，最终选定 100% / 85%。降低覆盖强度会混入未模糊的桌面；要保留明显磨砂，请保持高覆盖强度。它与附加模糊标准差、底板染色浓度是不同参数。
10. “阴影浓度”显示为百分比，JSON 的 `shadowOpacity` 为 0–1。阴影使用独立离屏圆角遮罩，与磨砂、文字淡化分别控制。

调附加模糊时，先固定“模拟聚焦 / 模拟失焦”、底板 0%、磨砂覆盖 100%。底板 100% 会完全遮住模糊层；低磨砂覆盖会透入未模糊桌面，掩盖模糊半径变化。确认半径效果后再调覆盖强度和底板。窗口后应放网格、文字或色块，纯色背景无法显著体现模糊差异。

最终启动参数已同步用户完成调参后的导出 JSON：聚焦/失焦附加模糊与底板均为 0；界面不透明度聚焦 100%、失焦 34%；磨砂覆盖聚焦 100%、失焦 85%；阴影范围 5、浓度 24%、偏移 2、圆角 24。参数快照见 `tuned-parameters.json`；启动进入跟随焦点模式。阴影浓度 0% 表示关闭样机自绘阴影。

**重要边界：** CreateHostBackdropBrush 本身带系统基础磨砂。滑块 0 表示没有额外 Gaussian 标准差，无法恢复成完全清透。实际输出不能标成“绝对模糊半径 0–64”。UI 已明确使用“附加模糊”。

## 架构

- `effects.rs`：依据 Windows SDK 的 IGraphicsEffect/IGraphicsEffectD2D1Interop 接口实现 Gaussian effect 描述，未复制 TranslucentTB 的实现代码。
- `composition.rs`：在 Tauri HWND 下创建 Windows.UI.Composition DesktopWindowTarget；host backdrop + Gaussian effect + 独立 tint，圆角几何裁剪；离屏 CompositionVisualSurface 提供圆角 alpha mask，SpriteVisual/DropShadow 只绘制阴影。图形对象限制在 UI 线程；不使用整窗 layered alpha。
- `layout.rs`：将逻辑边距转换为原生像素，提供 100%/150%/200% DPI 几何测试。
- `main.rs`：样机专用 IPC、窗口生命周期、焦点/缩放事件。关闭整个样机即可退出实验。
- `ui/index.html`：透明编辑区和参数面板。未使用 CSS backdrop-filter 来伪装桌面模糊。
- `ui/pattern.html`：独立背景参照窗口。

当前 Wry 的窗口式 WebView2 与原生合成层在本机可以共存，因此尚无证据要求替换为 Win32 + 视觉式 WebView2 宿主，更没有必要立即重写所有 React 界面。

## 已执行验证

- Rust 编译检查、release 构建；前端脚本语法检查。
- 两个几何测试：高 DPI 下原生内容范围与 CSS 一致；最小化时内容范围不会成为零/负值。
- 实际窗口初始化成功。后方动态计数/移动块在样机中实时变化，背景保持模糊，前方界面文字清晰。
- 最新 release 的真实焦点切换已检查：激活样机时原生读回附加模糊 12、底板 60%；激活独立背景参照时切换为附加模糊 4、底板 20%，仍保留实时磨砂。再次点击样机后恢复聚焦参数。焦点判断按 Windows 前台根 HWND，避免将焦点进入 WebView 子窗口误判为失焦。
- 固定“模拟聚焦”、底板浓度 0，比较附加模糊 0 和 64，可观察到明确变化；0 仍有系统基础模糊。
- 曾调节阴影范围与浓度，但用户反馈证实旧 LayerVisual 路线中间浓度有缺陷，原记录不作为通过依据。新遮罩路线的验收见 `docs/reviews/2026-10-28/shadow-debugging.md`。
- 样机圆角 25 的静态检查未见灰色直角；没有据此宣称所有桌面环境问题已解决。
- 在透明 textarea 中输入了“合成样机输入验证 ABC 123”，文字清晰可读；这只验证 Unicode 文本输入，不等价于中文 IME 候选/组合输入验收。
- 整窗 alpha 路线因失焦磨砂异常已撤回。用户明确选择保留明显磨砂、文字按钮单独变淡，因此现分别控制界面不透明度、磨砂覆盖强度和阴影浓度。
- 最终实际检查：纯阴影遮罩路线下 0% 无阴影、49% 四边连续较淡、100% 更重；真实失焦下界面 58%、磨砂覆盖 100%、附加模糊 64，动态背景网格仍明显模糊。

## 迁移前仍需验证

- 中文输入法组合态、候选窗口、长文本、多行、选区和滚动；普通 Unicode 注入不能替代这些检查。
- 最新一轮自动化未能确认 textarea 获得编辑焦点，因此未继续注入多行文本；此项仍待人工验收。
- 透明阴影边距的点击穿透、原生缩放命中区域；目前样机不承诺透明边距完全不截获鼠标。
- 贴边/展开/收起、内容矩形与阴影边距的坐标分离。样机没有实现正式版贴边状态机。
- 真实多 DPI/多显示器移动、100 次生命周期循环、设备丢失、长期资源与功耗对照、另一台机器。
- 是否需要低于系统基础磨砂的效果。如需要，本样机的 host-backdrop 路线不足以覆盖，不能只修改滑块标注后宣称支持。

详细决策依据见 `docs/reviews/2026-10-28/window-composition-assessment.md`。
